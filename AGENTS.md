# Repository Agent Instructions

This public repository is governed by its code, tests, public documentation,
issues and pull requests.

## Before changes

1. Inspect `git status` and preserve unrelated work.
2. Read the files and direct dependencies affected by the request.
3. State the intended files, validation and claim limits before editing.
4. Keep each commit focused on one authorized scope.

## Required boundaries

- Do not add private prompts, internal instructions, private repository URLs,
  local user paths, credentials or real customer data.
- Do not add artifacts from private cases, pedagogical systems or private
  evidence stores.
- Do not remove Gold masking or weaken the controlled local demo path.
- Do not claim production readiness, cloud validation, formal LGPD compliance,
  productive CDC/streaming, HA or enterprise secret management without public,
  reproducible evidence in this repository.
- Treat roadmap language as future work, never as implemented capability.

## Validation

Use the narrowest relevant tests plus mandatory security and boundary scans.
Changes to images, infrastructure or runtime contracts require their direct
build/render checks. Historical results never count as a new execution.

## Pull requests

Document what changed, why, affected contracts, validation performed and known
limitations. Do not include private links or copy private review material into
the PR.
